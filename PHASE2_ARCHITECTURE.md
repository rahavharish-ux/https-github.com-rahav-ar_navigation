# Phase 2 — Stage 3: Architecture

_Design proposal. Updated 2026-11-18 with the owner's decisions (see
`PHASE2_GAP_ANALYSIS.md` §0). Of this design, only the routing injection
seam exists so far (`routingServiceProvider`, added in M0); everything
else is still to build._

## 1. Principles

1. **Additive, not a rewrite.** Phase 1 layering (service → Riverpod
   `Notifier` → screen) stays. New capabilities are new modules behind
   interfaces; existing providers become inputs or fallbacks.
2. **Heavy pixels stay native.** Camera frames, AR rendering, and model
   inference run in Kotlin. Only small, typed messages (poses, detections,
   events) cross into Dart. Copying 30 fps camera frames over a platform
   channel is not viable.
3. **One camera owner.** When an AR session is active, ARCore owns the camera;
   perception reads frames from ARCore. When AR is off, CameraX (via the
   existing `camera` plugin or native) owns it. Never both.
4. **Graceful degradation is a state machine, not an `if`.** Every session
   runs at the highest available capability tier and steps down explicitly
   (and visibly) when a capability is lost.
5. **Uncertainty is part of the data.** Every pose, detection, and landmark
   carries a confidence/covariance. The UI shows degraded states honestly
   (continuing Phase 1's "no faked functionality" rule).
6. **Safety-critical guidance is deterministic.** Turn instructions and
   hazard alerts come from rule-based code. The LLM agent may explain or
   rephrase but never originates a safety instruction.
7. **No secrets on device** beyond restricted client keys. Any paid or
   keyed AI call goes through a backend proxy.
8. **On-device first, provider-independent.** Inference runs on the phone
   by default; every external service (routing, LLM) sits behind an
   interface with more than one possible implementation. Models and
   libraries must carry a commercially permissive licence (no AGPL unless
   approved).

## 4. Module boundaries and interfaces

Dart signatures are illustrative (final names are decided in each milestone).

### 4.1 Sensor acquisition — `SensorHub`

```dart
abstract interface class SensorHub {
  Stream<SensorSample> samples({required SensorSet sensors, required SensorRate rate});
  Future<SensorCapabilities> capabilities();
}

sealed class SensorSample { final int tNanos; } // monotonic (elapsedRealtimeNanos)
class OrientationSample extends SensorSample { final Quaternion q; final double? headingAccuracyRad; }
class ImuSample        extends SensorSample { final Vector3 accel, gyro; }
class StepSample       extends SensorSample {}
class GnssFixSample    extends SensorSample { final AppLocation fix; }
```
- Android impl: `EventChannel('tn_ar_navigation/sensors')`, batched (e.g. 20 samples/message) to limit channel overhead.
- Geolocator fixes are re-stamped with `elapsedRealtimeNanos` (Android provides it on `Location`) so all samples share one clock.
- `TraceRecorder` writes samples to JSON-lines; `TracePlayer` implements `SensorHub` for tests and offline replay.

### 4.2 Localization engine

```dart
abstract interface class LocalizationEngine {
  Stream<PoseEstimate> get estimates;
  void attachRoute(AppRoute? route);   // enables map-matching / progress
}

class PoseEstimate {
  final LatLng position; final double horizontalStdM;
  final double headingDeg; final double headingStdDeg;
  final double speedMps;
  final PoseSource source;             // gnss | fused | pdrOnly | vio | geospatial
  final RouteProgress? progress;       // distanceAlongM, crossTrackM, segmentIndex
  final int tNanos;
}
```
- Tier A (always): GNSS + PDR EKF (state: E, N, vE, vN, heading; local ENU frame).
- Tier B (ARCore tracking): VIO relative-pose deltas as a high-weight odometry input.
- Tier C (Geospatial localized): earth pose from ARCore used as an absolute measurement with ARCore's reported accuracy.
- `LocationProvider` remains the GNSS source and remains the fallback estimate. `NavigationNotifier` switches from `smoothedLocation` to `PoseEstimate` behind a flag, so Phase 1 behaviour is preserved until fusion is validated.

### 4.3 AR session bridge

```dart
abstract interface class ArSessionBridge {
  Future<ArStartResult> start(ArConfig config);      // geospatial on/off
  Stream<ArFrameState> get frames;                   // ~10 Hz to Dart, not 30–60
  Future<void> setRouteAnchors(List<GeoAnchorSpec> anchors);
  Future<void> setMarkers(List<ArMarker> markers);   // hazards, landmarks
  Future<void> stop();
}

class ArFrameState {
  final TrackingState tracking;          // tracking | paused(reason) | stopped
  final EarthState? earth;               // localized? + lat/lng/alt/heading + accuracies
  final Pose? localPose;                 // 6DoF in session frame
  final int tNanos;
}
```
- Rendering happens natively inside the `AndroidView`; Dart sends scene *content* (anchors, markers), never per-frame draw calls.
- Route → anchors: the Dart side converts the upcoming ~150 m of route polyline into geodetic points spaced every N metres; native creates Geospatial (terrain/rooftop or WGS84) anchors when Earth is localized, or local anchors from the fused pose otherwise.
- Without VPS localization, AR content placement depends on GNSS+compass accuracy (metres, degrees). The UI must present that mode as "approximate".

### 4.4 Perception

```dart
abstract interface class PerceptionBridge {
  Future<void> configure(PerceptionConfig c);   // models, rate, ROI, thresholds
  Stream<PerceptionFrame> get results;          // detections + tracks per processed frame
}
class Detection { final String label; final double score; final Rect box; final int? trackId; }
class Hazard   { final HazardKind kind; final Severity severity; final double? bearingDeg; final int tNanos; }
```
- Models: Apache-2.0 or similarly permissive licences only (decision 3), tracked in `LICENSES-models.md`.
- Native pipeline: `FrameSource` (ARCore `acquireCameraImage()` or CameraX `ImageAnalysis`, YUV) → resize/rotate → `InferenceEngine.run(modelId)` → NMS → IoU tracker → `Detection` messages.
- Rate governor: runs at most N Hz and skips frames when the previous inference is still running (no queue growth).
- `HazardRules` (Dart, pure, testable) turn tracks into advisory hazards (e.g. vehicle track in the lower-centre ROI with box area growing for K frames).

### 4.5 Edge inference — `InferenceEngine` (Kotlin)

- Model registry: `id → {asset, input spec, labels, delegate preference, max Hz}`.
- Delegate order: GPU → XNNPACK CPU. (Android's NNAPI is deprecated from Android 15 and is not planned.)
- Every model ships with a benchmark entry (device, delegate, p50/p95 ms) recorded in `docs/benchmarks/` once measured.

### 4.6 Routing

```dart
abstract interface class RoutingProvider {
  Set<TravelMode> get supportedModes;
  Future<List<AppRoute>> route(RouteRequest r);  // alternatives allowed
}
class RouteRequest { LatLng origin, destination; TravelMode mode; PedestrianPreferences? prefs; }
```
- `OsrmDrivingProvider` wraps the existing `RoutingService` unchanged. (M0
  already routes both notifiers through `routingServiceProvider`, which is
  where the `RoutePlanner` will plug in.)
- `OpenRouteServiceFootProvider` is the first walking provider (owner
  decision); Google Routes `WALK` or a self-hosted engine can be added as
  further `RoutingProvider` implementations without touching callers.
- `RoutePlanner` picks the provider per mode, ranks alternatives (time, crossings count, main-road exposure, hazard-layer penalties from §4.8), and explains the choice.
- `AppRoute` gains optional fields only (`mode`, `provider`, `warnings`) — existing constructor calls keep compiling.

### 4.7 Agent orchestration (provider-independent)

```
mic → SpeechIO.listen(locale: ta-IN|en-IN)  (platform recognizer; offline candidate: whisper.cpp)
    → transcript → AgentOrchestrator
    → LlmProvider.complete(messages, tools)   ← interface, no vendor types leak past it
         implementations (chosen by config, one active at a time):
           • OnDeviceOpenModelProvider   — open-weight model in LiteRT / llama.cpp (default target)
           • SelfHostedOpenModelProvider — same model family on our server (if phone is too slow)
           • HostedApiProvider           — e.g. Claude API, via agent-proxy; only after cost approval
    ← tool calls ← executed ON DEVICE by the tool registry:
         search_places, plan_route, start_navigation, where_am_i,
         whats_ahead (perception summary), read_sign (on-device OCR)
    → reply text → SpeechIO.speak(locale)  (platform TTS)
```
- `LlmProvider` is the only seam the rest of the app sees: a provider-neutral
  message list, a provider-neutral tool schema, and a result of either text
  or tool calls. Tool definitions live once, in the app.
- Decision 5: start with free/open-source components. Candidate open-weight
  models must be benchmarked for Tamil and English intent/tool-call
  accuracy, size and latency, and each model's licence checked (some
  "open" weights ship under custom terms rather than an OSI licence).
- A deterministic **intent fallback** (keyword/grammar rules for the core
  commands: navigate to X, where am I, repeat instruction, stop) works with
  no model at all, so voice control never depends on an LLM being present.
- If a hosted provider is ever approved, it is called only through a
  backend proxy holding the key (never on device), with per-user rate
  limits; its model and budget are server-side configuration.
- Tool results are summaries, not raw frames. No image leaves the device
  under the default configuration (decision 4).
- Offline: on-device provider and intent fallback keep working;
  deterministic voice guidance (GuidanceEngine) is unaffected.

### 4.8 Spatial intelligence / environmental mapping

- `Observation { id, kind (hazard|sign|landmark|sidewalk_quality|obstruction), geometry (point), confidence, source (vision|user), createdAt, expiresAt }`.
- Local-first: written to on-device SQLite; synced to Supabase table `observations` (PostGIS `geography(Point,4326)`, GiST index). Opt-in upload; images are not uploaded by default.
- Aggregated read model: a view/function returning confirmed observations by bbox, used as a hazard layer for routing and the map.

### 4.9 Session orchestration and capability tiers

`NavigationSessionController` owns one active session and exposes
`SessionState { mode, tier, guidanceCue, degradedReasons }`.

| Tier | Requires | Positioning | Guidance |
|---|---|---|---|
| T3 AR-Geospatial | ARCore supported + camera + Earth localized | Geospatial pose (+EKF) | AR world-anchored path + 2D + voice |
| T2 AR-Local | ARCore tracking, no VPS | EKF + VIO deltas | AR "approximate" arrows + 2D + voice |
| T1 Map | GNSS | EKF (GNSS+PDR) | 2D map + voice |
| T0 Degraded | GNSS lost | PDR only, growing uncertainty, time-limited | Voice + "position uncertain" banner |

Transitions are driven by `CapabilityManager` events (tracking lost,
VPS accuracy above threshold, thermal warning, camera revoked) and are unit
tested as a pure state machine.

## 5. Data flow during an AR walk (steady state)

1. `SensorHub` streams orientation/IMU/steps (50–100 Hz, batched) and GNSS fixes (~1 Hz).
2. `ArSessionManager` runs ARCore at camera rate natively; publishes `ArFrameState` to Dart at ~10 Hz.
3. `LocalizationEngine` fuses GNSS + PDR (+ VIO, + Earth pose) → `PoseEstimate` at ~10 Hz with route progress.
4. `NavigationNotifier`/`GuidanceEngine` consume `PoseEstimate` → maneuver state, voice cues.
5. Dart sends the next ~150 m of route as anchors to the AR view whenever the route or the anchoring frame changes.
6. Perception pipeline reads ARCore CPU images at ≤10 Hz → detections/tracks → `HazardRules` → advisory hazard cues (voice + AR markers).
7. Confirmed observations are written to the local store; synced when online.

## 6. Threading and performance budget (targets to verify, not claims)

| Work | Where | Target |
|---|---|---|
| ARCore update + render | Native GL thread | 30 fps minimum |
| Detector | Native background thread, GPU delegate | ≤ 60 ms p95 at ≤ 10 Hz on mid-range device |
| EKF update | Dart isolate (main is acceptable at 10 Hz; move to isolate if profiling says so) | ≤ 2 ms |
| Platform channel traffic | — | ≤ ~50 messages/s total, batched |
| Battery | Whole AR session | Measure; publish %/hour per device; set a target in M4 |

## 7. Testing architecture

- **Pure Dart cores** (EKF, map-matcher, hazard rules, tier state machine, geodesy, planners) — unit tests with synthetic and recorded data; no platform channels.
- **Bridges** — tested with fake channel handlers; one fake per bridge in `test/fakes/`.
- **Trace replay** — `TracePlayer` implements `SensorHub`; recorded walks under `test/fixtures/traces/` become regression tests (assert bounded error, not exact values).
- **Native** — Kotlin unit tests (JUnit) for post-processing and anchor math; instrumented tests for the inference engine on device.
- **Device protocol** — per milestone, a written checklist with device model, Android version, conditions, and measured numbers recorded in `docs/field-tests/`.
